Owned Data

Owner Proofs

ProofRequired assertion
Monotonic sequenceSuccessive next_frame calls emit increasing seq values from the configured start.
Lifecycle ownershipOnly Chunker advances next_seq.
Payload opacityInput Bytes are preserved exactly in the output Chunk.
No bufferingOne input payload produces exactly one output Chunk; no queue, batch, or retry state is introduced.

Integration Boundaries

BoundaryContract
Caller to mb-chunkerCaller supplies initial sequence and payload bytes.
mb-chunker to consumerConsumer receives Chunk and maps it into protocol or transport frames outside this owner.
Dependencybytes::Bytes is used for zero-copy payload ownership.

E2E Projections

  • Downstream reorder logic can rely on strictly increasing local chunk sequence.
  • Protocol adapters may map Chunk into frames, but framing semantics are not owned here.
  • Start sequence is caller-defined so session composition can coordinate sequence windows.
