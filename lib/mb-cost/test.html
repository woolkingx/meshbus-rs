Owned Data

ScoreInputs and Score are immutable value data. The module does not own I/O, timers, sockets, events, scheduler state, or mesh state.

TypeContract
ScoreInputsInput data for cost computation: RTT, jitter, success rate, price weight, goodput, and capacity.
ScoreComparable output. Lower is preferred. u64::MAX means unusable path.

Schema Source

schema.json declares this crate as a pure cost computation module. Concrete field shapes are implemented in src/lib.rs and imported by higher-level schemas through shared mesh-bus schema contracts.

Owner Proofs

ProofRequired assertion
RTT costLower RTT yields lower score when other inputs are equal.
Success penaltyLower success rate yields higher score; zero success saturates to u64::MAX.
Jitter penaltyHigher jitter yields higher score when other inputs are equal.
Saturation penaltyNo capacity means no penalty; utilization below 70% is identity; near capacity adds penalty.
PurityScore::compute has no side effects and depends only on ScoreInputs.

Integration Boundaries

ConsumerBoundary
lib/mb-cakeBuilds ScoreInputs from path evidence and chooses among returned Score values. Selection is mb-cake's responsibility.
mesh-bus-scheduler-cakeConsumes mb-cake scheduling output. Scheduler composition tests live there, not in mb-cost.

E2E Projections

  • Lower-score path is selected by scheduler composition tests.
  • Dead path is not selected when any live alternative exists.
  • Saturated path is deprioritized when RTT and success are otherwise equal.

These projections are verified by scheduler and product composition tests, not by mb-cost owner tests.
