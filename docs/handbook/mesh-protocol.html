Mesh Protocol

Mesh Protocol is the content-neutral N:N event fabric above core. It decomposes logical sessions into opaque events, distributes them across adjacent peers, ports, and paths, and lets the logical endpoint reconstruct session meaning without making TCP, UDP, QUIC, SOCKS5, HTTP, or any app protocol part of mesh truth.

Scope

scope -> mesh event/control -> protocol owner -> reconstruction gate

Mesh Protocol is not QUIC, not TCP, not UDP, not SOCKS5, not HTTP, not WireGuard, not a full-mesh routing protocol, not a channel protocol, and not a new application protocol. Its target is a native event fabric that moves opaque data packages across a mesh while preserving OSI owner boundaries.

TCP, UDP, QUIC, SOCKS5, HTTP CONNECT, DNS, and custom apps are client/server edge adapters. They project their own syntax into stream/datagram/application intent at the edge, and the remote edge projects mesh events back into the chosen egress protocol. Mesh Protocol never parses or owns their payload or protocol syntax.

The protocol is OSI-style event fabric, not TCP/IP-style tunnel. UDP ports, sockets, QUIC connections, and peer links are delivery coordinates only. Session identity, ordering, reliability, deduplication, reassembly, crypto envelope, path evidence, and delivery policy belong to the mesh/session owners, not to any adapter channel.

Canonical rule: this chapter owns Mesh Protocol semantics. Transport, plan, product, and compatibility chapters may reference this shape, but must not redefine Mesh Protocol around QUIC, TCP, SOCKS5, HTTP, or any delivery substrate.

Topology Contract

The stable product shape is protocol over mesh, never mesh over one protocol. Edge protocols are replaceable adapters; Mesh Protocol is the delivery and reconstruction contract between nodes.

Upstream Egress Model

An upstream is any selected egress owner. Local TCP, local UDP, local SOCKS5, local service adapters, and MeshPeer are the same scheduler category: they are exits that can accept a stream or datagram SDU according to their advertised capability.

MeshPeer is special only because its upstream is another bus node. It carries opaque L7 SDU bytes as MeshEvents to a peer, and the peer re-enters its own local pipeline to choose the final egress. This makes L7 over Mesh Protocol the canonical shape.

Product gate passed: stream-capable MeshPeer re-entry is implemented. SOCKS5 CONNECT, direct TCP, SOCKS5 UDP, and direct UDP can enter node A, cross Mesh Protocol as opaque stream/datagram events, re-enter node B, and exit through node B local TCP/UDP egress. Remote SOCKS5 stream egress is a required deployment projection of the same L7-over-mesh stream gate.

Data Shape Contract

Mesh Protocol follows the PCI / SDU / PDU rule from data-ontology.schema.json. A MeshEvent is the protocol PDU. Each owner may read and mutate only its own PCI; payload and upper-layer data stay opaque SDU.

ConceptContract
Event + DataPackageThe native unit. Event carries meaning and legality; DataPackage carries bytes. Combining them makes delivery independent from channel shape.
ChannelA receiver queue or ingress mouth. It is not the path, not the session, and not the protocol center.
QUIC streamA current compatibility/reference substrate for MeshFrame delivery. It is not the target design, not the owner of reliability, not Mesh Protocol, and not session truth.
Receiver hint / mouthDelivery coordinate. It helps find the right receiver and key, but never defines identity or routing truth.
Session id / flow idL5/L4 correlation data. They bind event reconstruction and scheduling evidence, not a transport channel.
Event payloadOpaque SDU to every lower owner. Lower layers may size, encrypt, fragment, forward, deduplicate, or reorder it only through declared PCI.

The current production path carries MeshFrame / MeshEvent data over Secure UDP and uses Mesh Protocol control frames for stream lifecycle. QUIC is a reference data-shape and comparison line only, not the owner of stream open, reliability, ordering, or session truth. Native mesh work keeps reliability, order, dedup, repair, striping, and reassembly in event-family PCI owned by L5/L6 over Secure UDP/MeshSec. QUIC may supply proven data-shape references such as packet number, ack range, stream offset, flow-control window, and path validation sample, but not its channel ownership model.

Event Fabric Invariants

invariants -> mesh event/control -> protocol owner -> reconstruction gate
  • A node stores local exits, configured parent peers, optional child peers, and aggregated capability views from adjacent peers.
  • A node does not require full topology, full peer list, global shortest-path routing, or route flooding.
  • `RouteAdvertise` updates metadata for a configured peer egress sink; it never creates a new `SinkId`.
  • Events forward hop by hop. Each next hop may re-enter its own bus and make a local L4 decision.
  • A logical session may be decomposed into MeshEvents and DataPackages, distributed across multiple peers, receiver mouths, and paths, and reconstructed only by FamilyState at the logical endpoint.
  • UDP ports and transport connections never define session identity. They are delivery coordinates selected by policy.
  • Opening or rotating a UDP port means announcing a receiver for future events. It is not opening, migrating, or owning a channel.
  • A channel or QUIC stream is a receiver/delivery surface only. It must not become the owner of route, identity, reliability, ordering, or reconstruction semantics.
  • Completing or optimizing QUIC is not completion of Mesh Protocol. Native event reliability over Secure UDP is the mesh protocol line.
  • TCP, UDP, QUIC, SOCKS5, HTTP, DNS, and application protocols are edge adapter contents. Mesh Protocol treats their bytes as opaque SDU.
  • Every advertised capability carries `hop_count`; receivers drop `hop_count >= MAX_HOP_DEPTH`.
  • A transport connection is path evidence and delivery substrate, not route truth, security truth, or session truth.
  • Transport address follows crypto: a peer's current delivery coordinate may be updated only after an envelope authenticates under the peer's accepted key material.

Route Advertise Aggregation

route-aggregation -> mesh event/control -> protocol owner -> reconstruction gate
  • A parent aggregates local exits plus capabilities received from adjacent peers.
  • Aggregation is sent only to adjacent peers; it is not flooded across the full topology.
  • Each hop increments hop_count. Receivers reject hop_count greater than or equal to MAX_HOP_DEPTH and log a warning.
  • RouteAdvertise never creates SinkId values. It updates availability and metadata for configured peer egress sinks.
  • Child nodes see the parent aggregated view, not the topology above that parent.
  • Scheduler may penalize hop_count, but core dispatch must not parse Mesh Protocol payload.

Delivery Segmentation

Delivery segmentation is an event-level contract between adjacent peers. The same encrypted event fabric may segment by event, DataPackage, flow, family, chunk, replica, or policy epoch.

UnitMeaning
eventEach event is independently delivered and deduplicated. Good for control, datagram, samples, and adverts.
packageOne DataPackage may steer, stripe, replicate, or repair independently from the transport port that carries it.
familyA family maps to a policy while L5 owns identity, ordering, and reassembly.
chunkStream chunks can stripe across receiver mouths and reorder at the endpoint.
replicaThe same event can be sent across multiple paths; the first valid event wins and later copies are dropped.
policy_epochA time-bounded delivery policy controls port pool, path pool, hash key, replica count, and reorder window.

DeliveryPolicy itself is a MeshEvent. It has epoch, expiry, and fallback semantics. Port selection is receiver allocation: a peer advertises where it will accept later events, and senders choose among those receiver mouths by policy. Unsupported policies fall back to single-port event delivery plus deduplication.

Delivery Policy

ModeUseRule
steerDefault path for cost-sensitive or stable links.Choose the best receiver mouth from LinkEvidence.
stripeBulk stream packages when RTT spread is small.Distribute consecutive DataPackages across mouths; FamilyState reorders by seq/offset.
replicateSmall critical events or stale/high-loss evidence.Send the same event to disjoint mouths; first valid event wins.
repairGap recovery and deadline-sensitive loss.Send retransmit or FEC parity through another mouth without changing family identity.
probeLow-rate exploration.Send bounded samples to refresh LinkEvidence; never creates route truth.

Policy changes require hysteresis, dwell time, and budget caps. Replication and repair are powerful but must not grow without cost limits.

Event Re-Entry

reentry -> mesh event/control -> protocol owner -> reconstruction gate
  1. Receive an envelope on any allowed port or binding.
  2. Use receiver_hint/key_id/epoch_hint to select the peer key and derive the event key.
  3. Decrypt and authenticate the MeshEvent. Failed decrypt is a fail-closed packet drop plus an obs.meshsec.drop owner fact; ciphertext and decrypted SDU stay opaque to observation.
  4. Validate ttl, path_trace, replay cache, event_id, and family-specific required fields.
  5. For open/control events, project the event into a local BusSessionRequest or policy evidence and run the peer node's local pipeline.
  6. Let local EventBus/L4 scheduler choose a local or remote exit.
  7. Preserve remote event/session identity and attach local FlowId/path labels for observation, dedup, reassembly, and close propagation.

Pipeline reject, no exit, expired ttl, replay, or unsupported event family returns an observable event where the family requires a response. Otherwise it is a fail-closed drop with a typed observation edge: MeshSec envelope failures publish obs.meshsec.drop, native event package failures publish obs.native.drop, and projections are defined by Dataplane and Observation.

MeshSec Security Model

MeshSec protects adjacent-peer event envelopes without making TLS, QUIC, or a channel protocol the source of truth. The lightweight profile is no-handshake PSK event encryption.

MeshSec has two separable scopes: hop envelope protection for adjacent-peer delivery and optional end-to-end event payload protection for logical session privacy across intermediate nodes. A transport binding may provide extra encryption, but that encryption is path evidence, not session truth.

ProfileContract
MeshSec-0RTT-PSK-XChaChaConfig stores a pairwise static_key. Sender derives epoch and per-sender traffic keys, uses XChaCha20-Poly1305, encrypts MeshEvent, and sends without handshake.
MeshSec-NoiseOptional hardened profile for forward secrecy. It may add Noise-style ephemeral key exchange, but it must still output encrypted MeshEvents and must not define session truth.
Debug-clearLoopback/test only. WAN deployment must not send clear MeshEvents.

Replay protection is event-level: receivers keep in-memory replay caches by peer, key epoch, nonce or event_id, and family sequence where applicable. Time slots limit key lifetime; they do not replace replay checks.

Static keys are identity and key material for a peer pair, not final traffic keys. Traffic keys derive from static_key, node pair, key epoch or time slot, direction, sender_id, and boot_salt. The same AEAD key and nonce pair must never repeat.

MeshSec Wire Contract

OffsetSizeFieldContract
01version_flagswire_version plus profile flags; reserved bits must be zero and AAD-covered.

Header bytes 0..22 are AEAD associated data. Fixed overhead is 38 bytes before padding. The inner plaintext starts with a 16-bit real length, followed by MeshEvent and zero padding to the selected bucket.

receiver_hint = HMAC-SHA256(K_hint, LE64(epoch_number))[0..8]. K_hint = HKDF-SHA256(static_key, info="meshsec/v1/hint"). Receivers precompute hints for accepted epochs and configured peer keys.

K_epoch = HKDF-SHA256(static_key, salt=LE64(epoch_number), info="meshsec/v1/epoch"). K_tx = HKDF-SHA256(K_epoch, salt=sender_id, info="meshsec/v1/dir/" || direction || boot_salt). Per-sender key derivation is mandatory for N:N; without it, independent senders can reuse nonce space.

Default epoch_seconds is 600. Receivers accept current, previous, and next epochs. Replay state is allocated only after AEAD success and is keyed by resolved sender_id, epoch, and boot_salt because boot_salt scopes the per-sender traffic key after process restart. Each key uses a 1024-bit sliding window over envelope counter plus L5 event_id dedup after decrypt.

Padding buckets are 128, 384, and 1024 bytes. Larger MeshEvents must be split by L5 before encryption; the envelope layer does not fragment one event across multiple packets.

Acceptance Gates

Local green: two-node raw UDP debug-clear datagram forwarding, two-node Secure UDP MeshSec datagram forwarding with packet-capture no-cleartext and tamper/replay fail-closed proof, route_group peer selection, tamper/replay fail-closed behavior, and metrics labels with node/peer/path/hop/wan evidence.
