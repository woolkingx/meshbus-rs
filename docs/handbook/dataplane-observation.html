Dataplane and Observation

Dataplane shape follows the accepted flow contract. Observation samples lifecycle, path health, and pull telemetry at the right cadence; it never turns byte movement into per-chunk control-plane work.

Problem

problem -> runtime fact -> observation owner -> metrics/readback gate

Per-chunk routing makes an L4 stream look like L3 packet dispatch. That adds channel wakeups, locks, observer wakeups, and broadcast fan-out on every chunk. The bottleneck is control-plane churn, not memcpy.

The retired T0 userspace fastpath bypassed the control plane to escape inline algorithms. The restoration removed that escape hatch: the hot path became pick, send, emit; scheduler feedback, metrics, health, and logging moved behind observer-owned subscriptions.

The correct replacement is not another bypass. Core derives a dataplane shape at open, commits eligible flows to direct halves, and keeps observers and schedulers in their own ownership domains.

Observation First Principle

observation-first-principle -> runtime fact -> observation owner -> metrics/readback gate

Observation facts are data. Owners emit typed facts or expose declared pull sources; observers derive projections. Metrics are projections, not owner state.

An owner fact is born where the owner can prove it. The MeshSec ingress owner can prove an authentication, replay, or native decode drop. FlowCounters can prove byte deltas. PathStats can prove RTT, loss, PMTU, pacing, and queue evidence. Projection observers can count, summarize, and export these facts, but they do not become the original owner.

Wrong: owner counter -> private snapshot -> metrics. Right: owner fact -> declared event or pull source -> observer projection.

The observation graph is a topology contract. A fact may move across modules only through a declared event, pull source, or projection edge. Logs are evidence for humans; they are not the first source of product metrics.

Substrate Correctness Before Speed

Dataplane optimization may only run on a correct L5/L4 substrate. A faster path that leaks session state, drops datagrams silently, misroutes observer events, or bypasses return semantics is rejected even when throughput improves.

GateRequired truth
L5 lifecycleForwarder close, session drop, eviction, and abort clean flow pins, flow states, counters, pending returns, and pumps exactly once.
Return semanticsDirect datagram is eligible only when return semantics can be preserved; reorder, reassembly, replicate, and multi-target flows stay FrameRouter.
Demux ownershipShared transport connections use one reader per connection and demux by session id; session recv halves must not consume another session's event.

Mid-flow shape switching is forbidden. Shape follows the contract at open, not momentary load.

Stripe-with-standby, Replicate, fan-out datagrams, route-changing sessions, and any L6 transform stay on FrameRouter even when a single path is carrying traffic right now.

Forwarder Lifecycle

forwarder -> runtime fact -> observation owner -> metrics/readback gate

A supervisor owns exactly-once lifecycle emission. Direction tasks report EndOfStream, IoError, Cancelled, panic, or protocol violation. First terminal error wins and cancels the peer direction. Half-close is internal state; FlowClosed emits only when both directions finish.

Per-chunk production cost target is one relaxed atomic byte-counter update per direction plus normal IO wakeup: no mutex, no observation publish, no broadcast, no channel send.

Direct stream forwarding is expressed through committed stream halves. The first accepted path opens the egress once; split session halves move bytes directly while lifecycle and counters remain visible to observers.

Datagram Forwarder

Fixed-target datagram sessions mirror the stream Forwarder handoff. Dispatch performs one approved direct-probe open, stores direct send/recv halves, and the L5 datagram session consumes those halves for later send_to and recv_from calls.

RuleReason
One realized path and no transform.Direct mode bypasses per-packet scheduling after open.
Fixed target only.A different target must fail or use FrameRouter before bypassing policy.
Recv returns the real source endpoint.The direct path must not fake a response through seq=0 or ReturnEvent::Data.
Unsupported direct open uses a typed fallback.Fallback is a one-shot control result, not ordinary idle polling.

UDP, QUIC datagram, and DTLS-style datagram egresses may use this surface through protocol-neutral datagram halves. Multi-target SOCKS5 UDP associations and fan-out semantics remain FrameRouter-owned.

Lifecycle events are reliable with a total publish deadline. Path IO errors and derived samples are lossy; terminal IO errors are followed by reliable FlowClosed so observers can reconcile state.

Pull Telemetry

pull -> runtime fact -> observation owner -> metrics/readback gate

`FlowCounters` owns bytes_in and bytes_out as lockless atomics. Samplers derive throughput windows by comparing snapshots.

`PathStatsProvider` is separate from egress plugin. TCP may provide RTT, rttvar, cwnd, send buffer usage, retransmits, and sample time. Non-socket transports may expose their own equivalent path telemetry.

Sampler observers use a fixed cadence and skip publication when counters did not change. RTT and path capacity never come from successful write completion; they come only from a declared path stats provider.

CAKE Closed Loop

closed-loop -> runtime fact -> observation owner -> metrics/readback gate

CAKE feedback is scheduler-owned, not kernel-owned. Metrics and health observers consume core lifecycle and path events, pull FlowCounters and PathStats, publish obs.path.rtt_sample, obs.path.throughput_sample, and obs.health.degraded, and the CAKE plugin consumes those derived signals on its own observer task.

The kernel may read the latest health snapshot while choosing candidates, but it does not update EWMA, jitter, goodput windows, saturation penalties, or hysteresis inline. That keeps the adaptive loop closed without making the dataplane hot path an algorithm host.

Acceptance Gates

gates -> runtime fact -> observation owner -> metrics/readback gate
  • Forwarder qualifies single-path ByteStream flows and preserves full-duplex, half-close, cancellation, panic, and exactly-once lifecycle behavior.
  • Core event surface stays exactly four variants.
  • Metrics and health observers use core events and pull surfaces; scheduler feedback lives in scheduler plugin crates.
  • MeshSec and native packet drops publish typed obs.* events; metrics, Prometheus, Operator, and diagnose consume observer projections.
  • Observation registry verifies all graph and declaration errors at boot.
  • Datagram flows use DatagramForwarder only for fixed-target, single-path, transform-free sessions; Replicate and multi-target flows stay FrameRouter.
  • Observer overflow does not block forwarding, and lifecycle reconciliation balances opened and closed flows under load.
  • The retired T0 fastpath, FastpathSend promotion/demotion, per-frame scheduler feedback calls, and BytesMoved push events do not return.
