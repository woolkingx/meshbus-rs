Product Skeleton

MeshBus-rs is the Rust implementation of MeshBus: an OSI-aware transport substrate for programmable direct proxy and mesh transport systems. It is not defined by SOCKS5, HTTP CONNECT, VMess, XRAY, QUIC, or any other edge protocol.

source intent -> metadata enrichment -> rule/policy -> scheduler -> exit | service | upstream peer

Direct forward and direct reverse paths are the foundation. MVP product lanes are L4 reverse TCP/UDP, SOCKS5 forward, and HTTP CONNECT forward. Compatibility protocols are reach; Mesh Protocol, Secure UDP, optional QUIC reference binding, multi-hop, striping, and reorder are amplifiers over that base.

Canonical chapter: product roadmap.

OSI Ownership

LayerOwnerBoundary
L7Application participantsTranslate external syntax into bus semantics only.
L6Transforms/codecsProtocol-neutral payload shape, envelope, fragmentation, checksum, compression, encryption.
L5Session planeSession identity, flow semantics, return semantics, lifecycle, path labels.
L4Scheduler/transportCapability matching, route_group, policy, path scoring, dispatch.
CoreKernel + transport substrateOpaque payload. No protocol parser dependencies.

OSI is a data ownership model. Each layer owns its native protocol data unit: the layer receives an upper-layer SDU, adds its own PCI and state, and produces its own PDU. Transport carries datagrams, crypto proves peer/event facts, L5 reconstructs logical sessions, and L4 chooses local paths from evidence. Channel state is always a projection.

The architecture question is always: what data is this, who owns it, and which CRUD or transition is legal for that owner. Lower layers carry upper-layer SDU as opaque data; they do not read upward-owned data.

Canonical chapter: system architecture. Root boot pointer: CLAUDE.md.

Direct Proxy Foundation

The direct path is rule-first, not speed-only. It makes source intent visible to rule/policy/scheduler before bytes move.

Forward

Direct stream/datagram source to TCP/UDP egress through normal pipeline selection.

Reverse

Local service exposed as scheduler-selectable sink, without an L7 route table in core.

Future Chain

Squid/Dante-like chaining after single-node direct foundation is proven.

Canonical chapter: direct proxy foundation.

Operator Plane

The system management interface is API-first. Config, status, metrics, probes, deployment, hot reload, Web dashboard, remote admin, and future cluster control compose through the operator plane, not through ad hoc CLI/Web logic or core dispatch shortcuts.

human/tool
  -> Operator API
       -> config/status/metrics/probe/deploy/rule owners
  -> CLI client
  -> Web client
  -> future MeshSec remote admin

Operational probes are traffic, not shortcuts: they enter configured SOCKS5, HTTP CONNECT, UDP, or mesh-peer paths and prove behavior by metrics deltas and close reasons. Diagnose bundles compose status, metrics, redacted config, host state, and journal facts without leaking secrets.

UDP / QUIC Transport

Delivery substrate mechanics, UDP packet loop, QUIC reference binding, and transport throughput gates live in UDP and QUIC transport. Mesh semantics are owned by Mesh Protocol.

Testing Gates

A feature is not complete until codec, adapter, core session/runtime, pipeline hooks, observers, scheduler behavior, binary e2e, and required live WAN smoke pass for the affected path.

Canonical chapter: testing gates. Generated topology: module test index. Execution guide: tests/CLAUDE.md.

Production Readiness

Production Readiness owns the deployment and operation layer: config check, service supervision, MeshSec fail-closed gates, secret redaction, metrics, live two-node acceptance, rollback, and release evidence.

local SOCKS5
  -> MeshSec MeshPeerUdp
  -> remote mesh node
  -> TCP / UDP / SOCKS5 / service egress

Rule: production support hardens this existing path; it does not create new core semantics.

Service readiness follows the owner graph: deploy checksums and backup artifacts, runtime config fingerprints, Operator probe deltas, MeshSec fail-closed evidence, and redacted diagnose artifacts.
