Compatibility Plugins

Compatibility plugins project external protocol syntax into protocol-neutral bus session semantics. They are application participants at the edge, not the product skeleton and not the core ontology.

Boundary

  • Protocol parsing belongs in codec libs or edge adapter crates.
  • Core receives target, flow semantics, return semantics, route_group, policy metadata, and opaque payload.
  • Compatibility labels may preserve protocol details for logs, but scheduler and core decisions must stay protocol-neutral.
  • Each plugin proves protocol correctness in its own crate and proves system integration through runtime/binary e2e.
  • A compatibility adapter must stitch L6 codec + L5 session control + L4 transport; it must not name kernel data-plane internals.

Substrate Pattern

An application protocol is not a new layer inside the bus. It is a stitcher over three existing surfaces:

SurfaceOwnerAdapter responsibility
L6 contentCodec or transform crateEncode/decode wire layout, such as method negotiation, request/reply fields, or datagram envelope.
L5 controlBus session surfaceOpen stream/datagram sessions, map typed close reasons into protocol replies, expose selected path metadata.
L4 transportKernel forwarding substrateMove opaque payload through route_group filtering, health, scheduling, fanout, and return semantics.

If a compatibility feature requires an adapter to reach into Frame, FrameKind, scheduler internals, or egress-plugin internals, the feature is misplaced. Add the missing L5 control affordance or L4 metadata field instead.

SOCKS5 command names are compatibility facts. New source metadata should prefer protocol-neutral ext.operation values such as connect and datagram_send.

Command/Auth Matrix

The authoritative support truth is the four-column `command_auth_matrix` in `lib/mb-proto-socks5/schema.json`: codec recognized, live ingress, live egress stream, live egress datagram. Adapter docs and tests must reference that matrix instead of restating divergent support.

A test asserting command or auth support outside its column is a contract violation.

CapabilityMeaningBoundary
Codec recognizedThe wire token is parsed and encoded by the codec library.Does not imply adapter negotiation or runtime support.
Live ingressThe client-facing adapter can accept the command/auth path.Must still project to bus session semantics or local relay behavior.
Live egress streamThe upstream adapter can open a stream tunnel through a SOCKS5 server.Requires handshake timeout and reply mapping.
Live egress datagramThe upstream adapter can maintain UDP ASSOCIATE control connection and relay datagrams.Control TCP lifetime owns the UDP relay endpoint.

Rules and Policy

Compatibility adapters may instantiate rule chains at their own boundary, but the rule engine is a pure DTO evaluator. It does not depend on core, codecs, or adapter crates.

Rule actionSOCKS5 projectionBus effect
AllowContinue normal CONNECT or UDP relay flow.No metadata change.
DenyReply RFC1928 connection-not-allowed where a reply is legal.Rejects before data relay.
SetRouteGroupWrite the route-group label into the session or event metadata.L4 filters candidates by declared group membership; no silent fallback on empty set.
SetScheduleHintProject fanout/single-path intent when compatible with stream/datagram shape.Runtime accepts compatible hints or returns typed unsupported errors.
SetCostBiasForward-pipeline metadata only.CAKE pick hook shifts effective RTT without changing payload opacity.

DNS Compatibility and Enrichment

DNS is not a core protocol parser and not an active port-53 listener in the canonical architecture. It is a resolver/cache/enrichment capability consumed by source adapters and the forward pipeline.

DNS pathCompatibility meaningCanonical boundary
Hostname passthroughA protocol such as SOCKS5 DOMAINNAME may carry the host end-to-end.The bus may route on projected labels, but core does not parse DNS.
Resolver hooknet.resolve_or_recover resolves hostnames or recovers host context from IP reverse map.Hook fills typed metadata and may reject no-target events.
Cache and serve-stalePositive, negative, reverse, and stale entries support decisions under upstream failure.Resolver-owned; cache TTL semantics do not leak into core routing code.
Geo/ASN/geositeEnrichment creates policy facts for route groups, cost bias, and diagnostics.In-memory hook data; misses become neutral facts.
DNS wire codecFuture explicit DNS adapters or resolver internals may use a codec crate.L6 codec only; kernel imports are forbidden.

Resolver inner rules and forward-pipeline rules are separate. Resolver rules choose pools before resolution; forward rules use post-resolution metadata such as geo, ASN, geosite tags, and DNS RTT.

Future Compatibility Lines

HTTP CONNECT, HTTP/3 CONNECT, VMess, XRAY, Shadowsocks-like protocols, DNS edge adapters, and transparent capture must enter as adapters. None may add parser branches to core or define route truth from wrapper state.

Readiness Rule

Local functional readiness means codec, adapter, runtime, and binary e2e pass for the affected path. Deployment readiness also requires env-gated live WAN smoke and metrics showing the intended upstream or peer path.

Compatibility completion is not declared by codec coverage alone. A path is ready only when the codec contract, adapter lifecycle, pipeline decision, session relay, observation, and boundary guard all agree.
