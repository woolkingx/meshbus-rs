UDP and QUIC Transport

Secure UDP is the native delivery line for encrypted Mesh Protocol events. QUIC and TCP are reference, fallback, and benchmark bindings. Transport connection, port, socket, and channel state are path evidence, not session truth.

Canonical Mesh Protocol semantics live in Mesh Protocol. This chapter owns delivery mechanics only.

Port Policy

UDP ports are delivery coordinates and receiver mouths, not service identity, not session identity, and not channels. A peer may expose an initial rendezvous port and then advertise a port pool through encrypted PortOpen / DeliveryPolicy events. The meaning is "send future events to these receivers", not "bind this flow to a channel".

PolicyContract
single_portAll envelopes use the configured rendezvous port. This is the safe fallback and simplest deployment profile.
port_pool_flow_hashFlow/session identity hashes to a stable port in the advertised pool to reduce reordering.
port_pool_event_hashEvent identity hashes to a port in the advertised pool, minimizing fixed delivery shape.
port_pool_replicateThe same encrypted event is sent across multiple ports or paths; receiver deduplicates by event identity.

Port policy is negotiated as event semantics. It must not create a channel or override L5 endpoint reconstruction. Port rotation is receiver reallocation only; event identity, deduplication, ordering, and repair stay in MeshEvent/L5 PCI.

UDP Packet Architecture Gate

The shared UDP shape follows Cloudflare quiche source as implementation reference: the application owns socket readiness, packet metadata, batching, pacing, PMTU guards, and path stats projection before throughput features land.

MechanismContract
UdpPacketLoopApplication-owned socket readiness, receive metadata, send batching, pacing hints, and path evidence.
UdpBatchSend / UdpBatchRecvOptional sendmmsg/recvmmsg capability for high PPS paths.
UdpGsoLinux UDP_SEGMENT only for one receiver address and one segment size per super-buffer.
UdpGroLinux UDP_GRO receive coalescing; split by cmsg segment size before Mesh Protocol datagram semantics.
UdpPacingSO_TXTIME/fq qdisc or userspace pacing fallback.
UdpPathMtuConservative guard first, future probe evidence later.
UdpBufferSizingOperator hint with warnings when OS limits refuse requested sizes.

Batching, GSO, GRO, pacing, and PMTU are transport-binding capabilities. They must preserve one logical Mesh Protocol datagram per message after receive-side splitting, and they must not change scheduler ownership or payload opacity.

Datagram Split Baseline

The L5 datagram contract exposes split send and recv halves so UDP ingress, UDP egress, SOCKS5 UDP ASSOCIATE, raw UDP mesh-peer, QUIC datagram, and future DTLS-style bindings can send and receive independently.

BaselineContract
Persistent sessionA datagram egress keeps a session/socket surface instead of opening a one-shot socket per frame.
Non-lockstep send/recvSend paths do not wait for the previous response before accepting the next datagram.
Endpoint preservationReturn mapping uses source endpoint semantics, not FIFO source guesses.
Protocol neutralityCore owns datagram halves and session lifecycle; protocol parsing remains in adapters.

Datagram Forwarder

Fixed-target datagram sessions may bypass per-packet dispatch after the first approved routing decision. The direct path mirrors stream Forwarder: open once, split send/recv halves, and return `(Endpoint, Bytes)` directly from the egress recv half.

EligibleFrameRouter fallback
Datagram flow, fixed target, one realized path, no transform, egress can open direct datagram halves. Fan-out datagrams, route changes, transforms, multi-target sessions, SOCKS5 UDP association-level multi-target use, unsupported direct egresses.

Direct-probe fallback must not reuse ordinary idle semantics. It must be a distinct one-shot control result.

Direct datagram mode is valid for UDP fixed target, QUIC datagram fixed target, and DTLS-style datagram bindings when security state is plugin-owned and no bus-level transform is required. SCTP-style reliable messages require a future message forwarder instead of being forced into datagram semantics.

MeshSec Binding

meshsec -> delivery unit -> transport binding -> path evidence gate
  • Production WAN UDP uses encrypted event envelopes. Clear MeshEvents are loopback/debug only.
  • The lightweight profile uses pairwise static keys from config, HKDF-SHA256 epoch derivation, per-sender traffic keys, XChaCha20-Poly1305, per-process boot_salt, envelope counters, and in-memory replay caches.
  • Time slots limit key lifetime. Replay protection remains event_id, nonce, and family sequence deduplication.
  • The outer envelope must not expose event kind, session id, node id, route_group, target, or payload.
  • Wire fingerprint minimization is an envelope policy: masked header fields, jitter, and padding buckets. It is not the cryptographic security boundary.
  • Envelope counter is crypto nonce material only; L5 event_id and family seq remain the owners of session dedup, ordering, and reassembly.
  • Machine contract: lib/mb-proto-mesh/schema.json.
  • Schema status: MeshSec and native event-package runtime status is owned by Mesh Protocol / MeshSec Wire Contract. This chapter records only how the transport binding carries those envelopes.

QUIC Reference Binding

quic -> delivery unit -> transport binding -> path evidence gate
  • QUIC may carry Mesh Protocol events for reference, fallback, and benchmark purposes; it is not Mesh Protocol and not the native mesh transport target.
  • The current compatibility path may map BusSession streams to QUIC streams, but endpoint reconstruction, reliability ownership, ordering, deduplication, and route truth remain mesh/session-owned.
  • Control, observation, and datagram events may use QUIC datagram or a dedicated control stream.
  • SPKI pinning binds peer identity to public key, not issuer metadata or route truth.
  • Connection migration may migrate delivery substrate but must not mutate EventBus route truth.
  • The implementation is own real QUIC (mb-quic) over UdpPacketLoop with a shared connection pool inside the transport binding. The Quinn reference binding was removed in M6 after own QUIC passed the same functional gates.
  • Mesh Protocol may borrow QUIC data shapes such as ack ranges, packet number spaces, stream offsets, flow windows, and path validation samples, but must not inherit QUIC stream/channel ontology or TLS certificate identity as mesh truth.

Raw UDP Binding

raw-udp -> delivery unit -> transport binding -> path evidence gate
  • Raw UDP carries best-effort control, observation, and datagram messages for loopback/debug and packet-loop experiments.
  • Raw UDP must reject reliable StreamOpen until an explicit reliable-UDP phase exists.
  • Source endpoint, node_id, peer_id, path_id, route_group, hop_count, bytes, datagrams, closes, and link samples feed the same path evidence shape as QUIC.
  • Production WAN UDP must use MeshSec envelopes; clear MeshEvents remain debug-only.

UDP Fast Path

UDP acceleration belongs to the L4 UdpPacketLoop owner. Mesh Protocol, QUIC reference delivery, SOCKS5, and rule plugins see only opaque datagram/event data and path evidence; they must not branch on kernel send mechanics.

PlanShapeOwner Rule
PlainSendmmsgone logical datagram per mmsghdrbaseline Linux batch path; preserves datagram boundaries
GsoSendmsgsame-destination, same-size datagrams coalesced into one super-buffer with per-message UDP_SEGMENT cmsgoptional L4 send-plan; never a socket-global option
FallbackEINVAL, EIO, or EMSGSIZE disables GSO for that socket/path and retries PlainSendmmsgcapability evidence, not route truth

Socket-level UDP_SEGMENT is forbidden for the current mesh substrate because it changes every send on the socket and can make a one-datagram-per-sendmmsg batch fail on older kernels. Real GSO is data-shaped: it is selected per outbound batch after the L4 owner proves that coalescing preserves the SDU boundary.

Acceptance Gates

gates -> delivery unit -> transport binding -> path evidence gate
  • Secure UDP carries encrypted MeshEvents and exposes no event family, session id, node id, route group, target, or payload in the outer envelope.
  • Raw UDP is loopback/debug only unless protected by MeshSec.
  • QUIC reference binding may carry event delivery across two nodes after Mesh Protocol re-entry is accepted; this is a regression baseline, not native mesh completion.
  • Both bindings report path evidence into the same PathStats shape.
  • Release matrix compares normal UDP, batching, GSO, GRO, GSO+GRO, pacing, PMTU, QUIC stream, and QUIC datagram where supported.
  • WAN smoke proves real remote exits and services with per-path metrics.
  • Raw UDP never claims reliable stream support before an explicit reliable-UDP phase.
  • Native mesh completion requires Secure UDP event reliability without assigning reliability ownership to QUIC streams.
  • SOCKS5 upstream UDP completion remains in the SOCKS5 compatibility line and does not block this transport architecture.
