Task Plans

Active work control for runnable files in docs/plan. This chapter owns status, dependency order, blockers, and verification gates; the plan files own task-level execution details.

Control Rule

handbook chapter = architecture and acceptance truth task-plans.html = active plan inventory and status docs/plan/*.md = runnable task breakdown tests/live gates = completion evidence

Every plan with three or more subtasks must appear here before execution. A plan can be active, blocked, superseded, or complete. Status changes must cite the verification gate that proved them.

Status Rules

status-rules -> runnable plan -> verification gate -> status truth
  • Blocked means a lower layer can make higher-layer test results misleading.
  • To execute means the handbook spec is ready and the runnable plan exists, but implementation has not passed gates.
  • Complete requires fresh command output, relevant unit/integration tests, and live smoke when deployment readiness is claimed.
  • Plan completion never changes architecture by itself; durable changes move into the owning handbook chapter.
