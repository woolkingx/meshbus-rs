Testing Gates

A module test proves only the module contract. A feature is complete only when the affected handbook gate, schema contract, codec, adapter, core/session/runtime, hooks, observers, schedulers, binary e2e, and live smoke gates pass.

Testing Thesis

  • Passing `cargo test -p one-crate` is never a system-complete claim.
  • Test evidence must name exact command, scope, and live environment.
  • Schema or handbook wording that carries contract meaning needs a test or boundary guard.
  • Schema is the natural data boundary. A test proves that an owner legally transforms schema-valid data.
  • E2e proves that multiple already-proven owner transforms compose into user-visible behavior.
  • Tests are owned by module data. A module that owns data owns the schema and the lowest contract tests for that data.
  • Root e2e tests compose module contracts; they must not duplicate codec, algorithm, reorder, crypto, or schema edge-case tests already owned by a module.
  • Handbook HTML defines the gate, docs/plan orders the work, CLAUDE.md governs execution, schema.json makes it machine-checkable, and tests prove it.
  • WAN/live tests are explicit and env-gated; missing env means local verified, live not verified.

Module-Owned Testing

The testing shape follows the data chain: data contract, schema contract, module owner test, cross-module integration test, then product e2e. A test belongs at the lowest owner layer that can prove the contract without importing higher-layer behavior.

The canonical test sentence is: a test proves that an owner legally transforms schema-valid data. The e2e variant is: e2e proves that multiple proven owner transforms compose.

Each module owner directory carries four local surfaces: CLAUDE.md for agent entry, schema.json for owned data, test.html for the proof contract, and code for legal transforms. The generated module test index scans these files and reports gaps; it is navigation only, not a second source of truth.

LayerOwnsExample
Data contractThe named data shape and owner boundary.LinkEvidence, MeshEvent, FamilyState.
Schema contractLegal fields, constants, ownership tags, and forbidden shape.Module-local schema.json or handbook-owned docs/handbook/spec/*.schema.json.
Module owner testThe owner module mutates only its own data and rejects illegal input.mb-proto-mesh codec tests, mb-reorder family-state tests.
Cross-module integrationOne boundary between two tested module contracts.mesh-peer UDP ingress consuming MeshSec + MeshEvent + UdpPacketLoop.
Product e2eComposition of already-tested modules into user-visible behavior.Two-node Secure UDP mesh path, SOCKS5 CONNECT through configured exits.

Module tests live with the module code and schema: Rust unit tests beside owner code when private invariants are tested, crate tests/ when the public module contract is tested. The workspace root tests/ directory is for cross-module test guidance and shared composition policy only; it must not become a second owner for module data.

Test Code Budget

Test code must stay smaller than runtime code because it proves the system rather than becoming another implementation. The target budget is test Rust LOC at or below one tenth of production Rust LOC after e2e consolidation. Temporary excess is allowed only while a reduction plan is active and each large test file has an owner and shrink path.

SurfaceBudget RuleRationale
Module owner testsSmall, data/table-driven, colocated with the owner.One module proves one data contract once.
Integration testsOne boundary per test file or focused group.Failures identify the boundary, not a hidden product scenario.
Product e2eFew hard user-visible paths only.E2e proves composition; it must not retest internals.
Perf/liveEnv-gated and reported separately from correctness.Numbers and live reachability are not module correctness.

A test that requires a large fake runtime, fake mesh, fake protocol, or fake scheduler is a boundary smell. The fix is to move the assertion to the data owner, expose a smaller public contract, or add one narrow integration seam.

Completion Rules

Feature-complete requires the narrow test, owning module test, runtime assembly if config/wiring changed, binary e2e if traffic path changed, and live WAN smoke if the claim includes deployment or WAN readiness.

Production-ready requires all relevant phases plus `cargo fmt --check`, `cargo test --workspace`, and `git diff --check`.

A skipped ignored test is not a pass unless the skip reason is explicitly named.

Loopback e2e can prove functional correctness. It cannot prove WAN readiness, throughput under real path variance, or remote-peer deployment safety.

Evidence Reporting

ClaimRequired wording
Local functional greenName the exact crate/binary commands and the passing scope. State that live WAN was not exercised when env-gated tests skipped.
Workspace greenInclude `cargo fmt --check`, `cargo test --workspace`, and `git diff --check`, or name the missing gate and why it was not run.
Deployment readyInclude the relevant live upstream or mesh-peer WAN smoke command, environment variables, target path, and observed metrics.
Performance readyInclude release-mode benchmark or relay matrix, baseline comparison, host/env notes, and whether the result is loopback or WAN.

Anti-Patterns

  • Do not claim system completion from one crate's unit tests.
  • Do not call loopback e2e a WAN live smoke.
  • Do not let tests build a second runtime, mock mesh, mock protocol stack, or duplicate scheduler.
  • Do not add an e2e test to compensate for a missing module owner test.
  • Do not hide skipped env-gated live tests inside "all tests pass".
  • Do not add protocol parsing tests to core to make adapter tests easier.
  • Do not update contract docs without a corresponding test or a reason why the text is non-contract commentary.
  • Do not use old Markdown plan/spec text as the proof source after the handbook has absorbed the contract.

Live Environment Gates

SOCKS5 upstream live smoke uses `MESH_BUS_LIVE_SOCKS5_UPSTREAMS`, with optional target host and port variables. Native mesh WAN smoke uses the Secure UDP / MeshSec peer topology and records absent env as not live-verified.

Report absent env as not live-verified.
