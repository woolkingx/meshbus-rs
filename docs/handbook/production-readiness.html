Production Readiness

Production support is the layer that makes the already designed substrate deployable as a service: config hygiene, service supervision, security posture, observation, live acceptance, rollback, and operator workflow. It does not add new core semantics.

Scope

This chapter owns production accessories and release gates. Product meaning stays in product roadmap, OSI ownership stays in system architecture, Mesh Protocol stays in mesh protocol, the management surface stays in operator plane, and proof rules stay in testing gates.

The first production profile is the personal encrypted SOCKS5 mesh proxy: local SOCKS5 ingress, native MeshPeerUdp with MeshSec, remote mesh node, and remote TCP/UDP egress.

Security Posture

RuleProduction contractGate
Fail closedA MeshPeerUdp WAN listener configured with MeshSec must reject clear, wrong-key, tampered, and replayed packets without creating higher-layer state.GATE-PRODSEC-01
No cleartext wire identifiersCaptured WAN packets must not expose MeshFrame magic, payload, route_group, endpoint text, node id, or target host.GATE-PRODSEC-02
Secret redactionRuntime config Debug, validation error, logs, metrics, and panic paths must not print PSK or SOCKS5 passwords.GATE-PRODSEC-03
Auth boundaryOnly configured peers may produce accepted MeshEvents; optional debug-clear transport must stay local/test-only.GATE-PRODSEC-04

MeshSec is an L6 transform module. It protects event envelopes; it does not authorize route policy by itself. Route authorization remains rule/policy data.

Observability

Production operation needs evidence for decisions and failures without inspecting payload. Metrics and logs must name owner data, not leak upper-layer SDU.

SignalRequired fieldsPurpose
Session lifecyclesession_id, flow_id, source, sink, route_group, close_reason, duration.Know which path failed and why.
Mesh peer linkpeer_id, mouth_id, path_epoch, srtt, loss, replay_drop, auth_drop, queue_drop.Prove link health and MeshSec behavior.
Schedulercandidate count, selected sink, policy id, health class, path evidence version.Explain route decisions.
Throughputbytes/datagrams in/out, goodput, retransmit/repair counts, per-exit saturation.Separate path limits from event/core overhead.
Configconfig fingerprint, schema version, enabled feature set, peer count.Make runtime state auditable after deploy.

Operator probes and diagnose bundles consume these signals as structured data. They must not scrape raw Prometheus text or journal text as their first source when a typed owner API exists. MeshSec/native drop evidence follows the observation drop contract: owner fact first, projection second.

Log Contract

Logs are operator evidence. They must explain owner state and close reasons without becoming a payload capture system.

LevelAllowed contentForbidden content
errorStartup failure, config validation failure, bind/connect failure, unrecoverable service failure.PSK, password, payload bytes, full HTTP/DNS content.
warnAuth drop, replay drop, clear packet drop on MeshSec port, route miss, resource pressure, peer unhealthy.Secrets, decrypted MeshEvent body, application payload.
infoVersion, config fingerprint, listener addresses, enabled features, peer ids, route groups, service start/stop.Raw config dump, key material, credentials.
debugLocal-only diagnostics behind explicit config or environment gate.WAN packet plaintext, unredacted config, long payload snippets.

Required labels: `node_id`, `source_id`, `sink_id`, `peer_id`, `route_group`, `session_id`, `flow_id`, `close_reason`, and `gate_id` when a log line proves an acceptance gate. Log redaction is a P0 production feature, not polish.

Policy and Rule Files

Production routing rules are data. They should be checked, fingerprinted, and logged as policy identity, not embedded as code branches.

DataOwnerProduction rule
route groupsRuntime configEvery ingress and egress names its allowed groups. Missing group means deny or explicit default, never accidental all-access.
policy rules/etc/mesh-bus/rules/Loaded from schema-valid files with fingerprint in startup logs.
peer capabilitiesMesh peer observation/controlSoft evidence with epoch and TTL. It never creates permanent config truth.
deny rulesPolicy layerDeny beats route selection. Close reason must report policy reject without leaking payload.

Operator Workflow

  1. Build release binary and record checksum.
  2. Generate or load MeshSec key material from protected operator storage.
  3. Render local and remote YAML from schema-valid templates.
  4. Install or update rule files and record their fingerprint.
  5. Run `mesh-bus check --config ` locally and on the remote host.
  6. Install binary and config with previous files retained as rollback artifacts.
  7. Restart through service manager and confirm `active` state.
  8. Run secure two-node SOCKS5 UDP and CONNECT smoke.
  9. Capture WAN packets and run no-cleartext plus fail-closed probes.
  10. Inspect journal logs for startup fingerprint, listener set, peer set, route groups, and absence of secrets.
  11. Run selected release throughput matrix only after correctness gates pass.

Non-Goals

This chapter does not define new protocols, add L7 parsers, replace Mesh Protocol semantics, or make a production security claim from loopback tests. It only defines the accessories and gates required to operate the existing substrate honestly.
