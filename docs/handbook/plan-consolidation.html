Consolidation Rule

plan content -> recovered durable topology/logic goes to handbook owner chapter -> recovered data/structure contract goes to schema.json -> remaining steps stay in docs/plan

Do not treat any plan as the canonical architecture source. When a plan contains durable design, status, or testing content, move that content into the owning handbook chapter or schema contract before code relies on it. The full hierarchy is defined by Documentation architecture.

Durable Contracts Recovered From Plans

AreaRecovered contractOwner surface
L4 session abstraction External protocols must enter through StreamSession or DatagramSession style L4 session surfaces. Raw frame use inside plugins is a migration smell. `mesh-bus-core`, ingress/egress adapters, module CLAUDE files.
Pipeline and rule engine The stable shape is source -> pipeline -> wiring -> sink. Event pipeline is control flow, decision flow, and session flow; payload bytes remain transport data, not core event payload. `mesh-bus-runtime`, `mesh-bus-pipeline-hooks`, `mb-rule`.
Dataplane observation Dispatch must emit observable decisions and failures. Observers consume metrics, health, CAKE feedback, path labels, and scheduler evidence without owning byte movement. `mesh-bus-core`, observer crates, scheduler crates.
Datagram path Datagram send and recv are split. Forward path must not lockstep send_to with recv_from. Direct datagram forwarder applies only when session target semantics are compatible. `DatagramEgressAdapter`, ingress UDP, SOCKS5 UDP, UDP egress, datagram forwarder.
Mesh peer Adjacent peer is the routing unit. Secure UDP MeshSec is the production event substrate. Raw UDP is debug/local. QUIC provides reference/fallback/benchmark streams and datagrams only; its connection pool is path evidence, not mesh session truth. `mb-proto-mesh`, raw UDP peer crates, QUIC peer crate, runtime schema.
Compatibility SOCKS5, HTTP CONNECT, transparent capture, and future protocols are adapters. They project external syntax into bus session semantics and must not redefine the product skeleton. Ingress/egress compatibility crates and protocol codec libs.
Testing process Feature completion requires narrow tests, owning module tests, runtime assembly when config/wiring changes, binary e2e when traffic paths change, and live WAN smoke when deployment or WAN readiness is claimed. Testing gates, tests boot card, binary e2e, env-gated live tests.
